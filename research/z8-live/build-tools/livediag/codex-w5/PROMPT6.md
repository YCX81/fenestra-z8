Read-only feasibility analysis, in Chinese. Do not modify anything, no USB calls. Label each claim: proven by disassembly / proven by hardware reading / inference. Files: bg34.main (running Nikon Z8 MAIN, load base 0x40160000; stock outside hooks and payload 0x401e2000..0x401fff80), src-fix31/ (Live payload; capture/ takes live-view frames, codec/live_w5enc.c encodes), v14..v20 patches (scaler diagnostics and channel-2 experiments), ch2buf.py, regwatch.py, history/hw-notes.md (hardware notes; the scaler section matters).

Goal: Live clips are 1024x682 from scaler output channel 1 and look soft and aliased (vertical pole shows mosaic-like patterns). The owner wants at least 1280x852, the size of the scaler input, in photo mode, without HDMI.

Known: scaler input block 0x15421000, 1280x852 4:2:2. Outputs F_k=0x15423000+k*0x100 (+0x10/+0x14 ratio Q14, +0x2c/+0x30 out size, +0x04 mode 1/3/4), B_k=0x15422000+k*0x100 (+0x0c format, +0x38/+0x3c stride, +0x00 reset pulse, +0x04 kick, +0x20/+0x24 Y address). ch0 640x480, ch1 1024x682, ch2 1920x1080 NV16 for HDMI in image bank 1, never written in photo or movie mode without HDMI. v17 wrote ch2 to 1:1 1280x852 NV12 with a run bit: writes took, buffer stayed unwritten. v19 kick variants a/b (keep mode 4 + B2 reset/kick, or mode 1) exist in the firmware (livectl ch2 a|b|off) but were NEVER tried on hardware. Live must capture a stable frame by reading the C0 snapshot 0x40c269cc (Y=s[3+k], UV=s[10+k]). Host debug reads of 0x154xxxxx hang the camera; only camera-side 32-bit loads of firmware-programmed offsets are safe. The Wave5 encoder accepts sizes up to 1920 wide but slots were sized for the frame; encode currently ~4 ms per 1024x682 frame.
