# Native REC 比例窄补丁：独立 ARM 审核

**通过下一步整机验证，未找到阻塞合入的反例。** 这是原厂计算路径的精确执行检查，未证明真机 LCD/EVF 可见、自动旋转正确，也不是刷机验收。

审核对象为 root `crop-fix/aspect_fix.bin`，64 B，SHA256 `87678087a29c0389a4342651ae7ee0162e5c664eb25355b989d2e452fc08f593`。exact G MAIN SHA256 `ed1e8496fccde443412e527a252de5029a55c749053b9b046da42bfc454aa613`。没有修改 root 源码或固件；候选入口和 cave 仅写入独立 Unicorn 测试内存。

## 可证明的路径

- 原 `0x407138d0` 的指令确为 `B 0x409708f0`。候选改成 `B 0x4019fc80`，仅当 w2=0 且源尺寸为 1024×682 或1280×852 时令 w2=1，之后尾跳回 NFP `0x409708f0`。
- NFP wrapper 仍进入 `0x40960a00`，该 trampoline 执行原被覆盖的栈保存后返回 `0x407138d4`。原 `memcpy 0x4127a900` 和整段原厂尺寸/对齐/居中计算都实际执行。
- 原厂 mode0 分支固定计算16:9，mode1固定计算3:2；源宽高仅用于选择哪一边受限。最终原厂仍强制横向16、纵向8像素对齐。两种 Live 文件并非数学上恰好3:2，余下不到一个对齐单位的比例误差来自这条现有原厂路径，未新增另一套计算。
- NFP随后读取原变形镜头偏好并按原ROM表调整输出高度：Off、5/4、13/10、4/3、3/2、8/5、9/5、2/1。全部8个分支实际执行，不模拟它们的结果。
- NFP另有照片文件匹配时强制3:2的前置分支。测试同时覆盖启用/未启用；候选保持该分支输出。

## 结果

8448组：12种源尺寸 × 4种mode × 11个输入记录 × 8个NFP选项 × 2种NFP照片覆盖状态。128组输出有变化；目标两尺寸mode0的完整28 B输出逐字节等于“原NFP+原厂mode1”，其余情况与原版逐字节相同。非匹配包括1024×680/684、1280×854、互换宽高、1080p/4K/8K、零和65535边界，以及mode1/2/UINT32_MAX。

每次调用同时断言：NFP wrapper/trampoline/原厂入口都实际到达；x19..x29、SP保持，28 B输入不变，输出两侧哨兵不变，只写输出与原栈，没有显示MMIO访问。G中拟用64 B cave为全零；**最终整合版仍须独立检查PB增长/其他cave占用和原入口严格字节**，不能复用G的空闲证明。

## 证据边界

4个实际输入记录来自 `evidence/probe-n3/trace-small.jsonl` 的 `0x40718484` 调用，原始112 B存入 `actual-input.json`。当时选择LCD，因此只有第一个记录active；激活EVF及竖屏、偏移、PAR是明确标记的helper输入fixture。它们验证helper在这些形状下不拉成16:9、不越界，不能证明原厂整个旋转pipeline会传入同样的记录。
