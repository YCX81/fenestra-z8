## Native protocol, not inferred from function names

- Write 40c7f824: CS low through original 40c15c3c, two halfwords `[register,value]`, then CS high.
- Read 40c7fd08: CS low, halfword `register | 0x8000`, separate transfer TX=NULL/RX=one halfword, CS high only after return.
- 40c8088c builds the 32-byte serial descriptor and calls 40ca4a1c with handle10. The latter selects service entry a02813f00, whose +8 is low-level object a02808b90.
- 40c1459c copies the descriptor into the controller object. **40c14624..40c14630** checks control register +0xc bit5: for a null TX source and RX1 it may set low-level TX-needed to1. For the actual RX helper flags4, **40c15354** emits an actual zero FIFO word after RX-empty handling;40c15224 is the alternate flags2 branch. This is a clock word generated by native instructions, not payload from RAM.
- The controller's 16-bit receive FIFO and ordinary pending/IRQ path remain authoritative. No PC, service return, callback, RTOS event, or guest status is replaced by the peer.

`native-tests.json`: eight actual ARM cases. Six execute codec wrappers/GPIO/service while declaring the low-level serial leaf shim. Two separately execute the real low-level initializer and PIO sender: bit5=0 gives TX-needed0/no FIFO write; bit5=1 gives TX-needed1 and an actual zero FIFO write. The GPIO table address in this small ARM fixture was explicit; real QEMU subsequently observed d151014 independently.

## Bounded peer contract

Opt in with `codec-spi-register-peer=on`. `codec-spi-register-state` exports counters, most recent descriptor, control word, FIFO word, and refusal reason.

1. Bind exact native codec globals, handle10, GPIO bank5/pin13 enabled object, original RAM GPIO table, service pointer, and native object10. Only RAM is inspected; the peer does not read display/MMIO through guest pointers.
2. Check actual PIO16 controller/no DMA, current CS assertion, native descriptor/mode, and real FIFO words against original TX RAM.
3. Remember only complete writes to15/16 terminated by CS high. No default or identity register value is supplied. Unknown commands do not receive a response.
4. Recognize only8015/8016 and preserve that command across the two transfers while CS remains low.
5. For bit5=0, accept only TX-needed0/RX1. For bit5=1, accept only TX=NULL/TX-needed1/RX1 and wait for the one actual native FIFO zero. Consume that clock word and enqueue the retained response, then call the existing FIFO/IRQ updater. Every new controller enable uses the original PIO reset code, including clocked=0.
6. CS changes invalidate the pending command. Read/write budgets are1024 each. FIFO shape, wrong binding, invalid memory, missing history, and extra/wrong clock words refuse completion.

This is a functional register-retention input. It does not identify a physical codec, model analog gain, DSP execution, microphone acoustics, or measured SPI timing. Other register writes are neither interpreted nor used to synthesize reset values.

## First failure retained and correction

V1 full native run had writes2/valid3 (15=0,16=0x100), reads0/rejects1/pending1/CS low. The command reached the model; the RX guard rejected the second phase. It had required TX-needed0, omitting the native dummy-clock branch described above. V1 is archived, not relabeled a pass.

V2 adds only that specific branch and raw refusal diagnostics. `host-tests.json`:71 actual peer C cases under ASan/UBSan. The harness invokes the original `serial_enable` PIO branch for phase transitions and verifies clocked resets, instead of manually assuming its value. Includes wrong owner/mode/source/value, CS cancellation, no history, repeated response, unknown registers and dummy-clock counterexamples. Full native SPI completion is now evidenced in `v2-native-proof.json`: control_c=39(0x27), tx-needed1, queued1, word0, reads2/rejects0; actual GPIO table d151014. In the REC lane, worker polling continued and original stop_ack1/driver1 followed. This does not establish video source/Ready/photo success.
