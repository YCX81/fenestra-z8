Nikon Z8 测试包 3a-diag（Live 抓帧诊断版）
基础：测试包 3a（Z_8_0405.bin 73042c26…，MAIN 919a6545）。版本标识 04.05.p0，相机里显示的版本号不变，以 SHA-256 辨认。

用途
- 真机上 Live 一帧都抓不到（USB 读到：取景约 30 帧/秒，Live 处理循环每秒只跑约 2.3 次，处理过的帧全部判为无效）。
- 这个版本只在 Live 的抓帧和处理循环里加了计数和计时，Live 的行为和 3a 完全一样，其余功能（滤镜槽、i 菜单修复、回放、USB 调试默认开启）不变。
- 记录内容：每一帧在哪一步被拒绝（过期、采样间隔、取地址失败、复制前/后校验失败、复制期间来了新帧、被取消、编码忙）；
  取地址、复制转换各花多少时间，复制期间来了几帧；实际的画面地址和行宽；工作循环里界面、抓帧、录音、休眠各花多少时间。

和 3a 的差别（已逐字节核对）
- 只有 Live 代码区（0x401e2000 起）和 Live 原有的 15 个挂钩点不同；其他地方与 3a 完全相同。
- 构建链与 3a 相同：Live 层 → 回放层 → USB 调试默认开 → 界面对象池修复。用同一条链编原版源码，结果与 3a 的 MAIN 919a6545 逐字节一致。

QEMU 验证（MAIN 94e4ec8b）
- 关闭 Live 单拍：2/2 正常保存 DSC_0001.JPG。
- 打开 Live：诊断数据块（标识 LDG1）能读出，计时、计数正常；连拍在第 107 步因 QEMU 没有 Wave5 模型停下，与 3a 原版停在同一步、同一条指令。

使用方法
1. 刷机：Z_8_0405.bin 拷到卡根目录（FENESTRA 文件夹与 3a 相同，卡上已有的可不动），SETUP → 固件版本 → 更新。
2. 开机，确认 Live 打开、USB Debug 打开，USB 接 win-lab。
3. 停在拍照取景界面（不要进菜单），保持 10 秒以上；需要时按几次快门。
4. 由我通过 USB 只读读取诊断数据。读完拔掉 USB 线，不要插着线闲置。

已知
- 从回放回到取景后 Live 图标可能不再显示：图标没重画，Live 本身仍在“已请求”状态。本版不改这一点。
- 真机上 Live 仍然不会产生片段，这一版只用来找原因。
