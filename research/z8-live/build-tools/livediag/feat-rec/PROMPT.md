In Chinese. Write only inside this folder. No USB, no flash, no touching the camera.
Design and write a diagnostic-only "flight recorder" for a Nikon Z8 firmware payload, as a patch script on src-fix35/ (v35 = current build), not changing the hand-back or REC flow. bg34.main is the running MAIN family (base 0x40160000; stock outside hooks and payload region 0x401e2000..0x401fff80; check hooks.S, relive tooling in src-fix35 for how hooks and trampolines are declared; do not assume). history/ has all prior analyses, especially astra-bbzen9eh9.md, astra-bmbt670bc.md, astra-bkdhewcl4.md, astra-b5o959yx8 facts (GPIO 139 card lamp, stock output 0x40c15c3c, descriptor 0xa0280a1b0, level 1 = lit, confirmed on hardware).

Hardware state: Live has run; REC pressed; the 0x402f2d58 hook runs and returns after about 1.7 s; recording never starts; 18-27 s later the camera reboots. Records flushed by Live's worker never reached the card in that window (the worker flush works in photo mode), and v35's blink code after the hook never appeared (its cause unknown: once flag pad33, or lamp_wait/DELAY after EXIT).

Required, in order of priority:
1. Synchronous write from the REC caller task at the end of the hook's close: complete Wave5 state record (fin_rc stage, workers, slots, core busy, svc_up, VDI, arena, client map, close_failed, instance slot), via a pre-created fixed-size file on the card rewritten in place, with the file created at safe time (worker, photo mode, or boot). Must not use a time-dependent DELAY: use a counter-based busy delay where a delay is needed.
2. Probes at stock points after the hook, each adding a record and a synchronous write before the next risky call: return of service open at 0x402f303c (rc), REC caller after bring-up (0x40d07ba8), adapter start entry 0x402f5870 and before its wait 0x402f58c8, adapter task steps after each of OPEN/CONFIGURE/REGISTER/SET_PARAMS/HEADERS/RUN and the completion event at 0x402f4c18. Choose the smallest set, check that each patched instruction is safe to relocate (no PC-relative, or handle it), and verify every address against the instruction bytes in bg34.main. Note these are different tasks (MOVRS, adapter task), so writes need serialising without deadlock, with bounded behaviour.
3. Card lamp lit immediately before each write and off after, so a hang inside a write is visible; lamp on/off is the only visible mark and must be cheap.
4. Keep the on-card format simple, with a decoder script in Python producing a readable table in Chinese labels.
Deliver: recorder_patch.py, hooks changes needed, decoder, README with each probe address and its verification evidence, the worst-case added latency, every risk (boot, photo mode, playback, REC), and exactly what a result means (decision table), and how to recover. Do not claim anything is hardware-tested. Compile-check if a suitable aarch64 cross compiler exists, otherwise say so.
