# Actual-duration JPEG preview candidate

Base: immutable `feat-v53/integration-f/work/src-fix37`. Only the four files in `changed-files.json` change. No runtime structure, allocation, layout, function pointer, stored JPEG/audio location, MOV track/Apple pairing or original integration file changes. `live_preview_write` gains one trailing scalar argument; its single production caller passes the same `lastPTS-firstPTS+last_duration` already validated by successful MOV finish.

The old LVJ1 writer always declared 45 × 66667 µs and the preview frame supplier also sampled at `clip_start + i*66667`. Changing only the header would stretch the first three seconds of pictures. The candidate records a uniform `ceil(actual_duration/45)` interval and selects each JPEG at `clip_start + i*(clip_end-clip_start)/45`, using the existing chronological preview ring and existing nearest-earlier policy. Targets cover the real frozen interval rather than a fixed three-second subset. The oldest available picture still supplies times before the ring's oldest timestamp; this existing finite-ring behavior is retained, not described as a newly recovered missing frame. The last target remains strictly before clip_end.

LVJ1 version/header/trailer remain compatible with the existing reader. Its integer per-picture interval has up to 44 µs extra duration, never an early image EOS. For example, the 3,069,733 µs test clip produces 68,217 µs × 45 = 3,069,765 µs. The maximum representable duration under the unchanged reader's four-second cap is 3,999,960 µs; 3,999,961 and 4,000,000 are rejected before writes rather than producing an unreadable atom or clamping the timeline. Zero, very short and overflowing durations also fail. This explicitly tightens the standalone writer contract; it is not a general arbitrary-duration media writer.

The current production capture initializes window_us to 1,500,000 and has no code writer changing it. Its fixed 30000/1001 profile and GOP15 add less than 500,500 µs before the requested pre-window and less than 33,367 µs after the post-window. With valid consecutive native IRAPs the normal maximum is below 3,533,867 µs; short-start requires a 500,000 µs old IDR before Ready, giving approximately two seconds minimum. These production windows fit the existing reader. This bound depends on that fixed profile and normal validated native IRAP cadence; external mutation of debug tuning or malformed encoder output is not covered by this contract.

`test_duration.py` compiles the full actual writer/reader and the verbatim sampling function with ASan/UBSan. Six successful files cover short/normal/long/upper-bound spans, wrapped ring slots and clamping outside available preview timestamps; the old header and old sampling implementation independently fail their counterexamples. Six invalid durations cause no frame requests or writes; invalid index, no frames and invalid clip span fail. Existing reader EOS/epoch checks and optional LVJB parsing pass.

`test_transaction.py` compiles the actual complete transaction writer. A real 95-AU input with actual 3,380,975 µs PTS span produces 45 × 75,133 = 3,380,985 µs. Full audio, unavailable audio and partial-read fallback all save successfully with the same correct image duration; metadata failure and cancellation roll back. Evidence and generated files are under `tests/`. Test fixture AUs, timestamps, audio and source JPEG are unchanged. These are host tests, not final linked ARM or camera validation.

Old fixed-header files are handled separately by the audio agent's PB EOF hold, preserving old JPEG cadence until the bounded started PCM reaches its end. That PB fix is required independently of new-file duration metadata.
