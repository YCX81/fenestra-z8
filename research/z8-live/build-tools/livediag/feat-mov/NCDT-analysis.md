# Nikon metadata：外层结构与实际内容分开判断

> 本页记录 11 月 9 日仅凭反汇编分析的阶段。当时的“缺 donor / 缺模板”是该阶段的样本条件。11 月 10 日已从历史 QEMU 产物取得完整 NCDT，并实跑当前 MAIN 的解析入口；仍缺在这台 Z8 上确认可播的实机正对照。[更新的 NCDT 证据](FIRMWARE-NCDT.md)

本轮仅离线反汇编当前 `bg34.main`，基址 `0x40160000`；SHA-256 为 `c7c6dbeea8a94064a10d47a7b9022ab26e4aa6b12ba5fb63b1ad85abac4fe4d4`。它是运行 MAIN 的文件快照，不称其为未修改的原厂镜像。证据见 `evidence/ncdt-disassembly.txt`、`evidence/nctg-disassembly.txt`；`python3 evidence/disassemble.py` 可用本地 Xcode 重建。反汇编未执行固件。

## 本轮新增的内容约束

【反汇编证实】`0x406befc0` 的缓存结构基址为 `0xa04560628`。每个已识别盒登记 payload 相对偏移、payload 长度及指针。下面的结构偏移不是 MOV 文件偏移。

| 盒 | 缓存字段（offset / length / pointer） | 实际检查与后续用途 |
|---|---|---|
| NCHD | +0 / +4；无独立 pointer | 总长 18；`Nikon\0`；payload[6] 为 1 或 2；payload[8:10] 为 0。payload[7] 在此段未检查。 |
| NCTG | +8 / +0xc / +0x10 | 外层只要求存在；非空才调用 `0x406ce344`，得到 metadata 状态与解析结构。 |
| NCTH | +0x18 / +0x1c / +0x20 | 外层只登记；`0x406c0dd0` 的缩略图分支要求长度 1..65536，给出固定 160×120。**这只是入口长度/尺寸条件，不证明任意字节可解码。** |
| NCVW | +0x28 / +0x2c / +0x30 | 后续要求长度 1..0x300000；尺寸来自解析后的 NCTG 结构 +0xc4/+0xc6。 |
| NCDB | +0x58 / +0x5c / +0x60 | payload 被当作子盒序列扫描，最多 16 项；识别 `OP01`、`OP02`，记录各自 payload offset/length 于 +0x68/+0x6c、+0x70/+0x74。未知子盒跳过；每盒至少 8 字节且不得超过 NCDB 末尾。 |

【反汇编证实】外层最多扫描 16 项，最终在 `0x406bf330..354` 检查五个 **payload 偏移非零**，并非五个 payload 长度均非零。NCTG 非空分支位于 `0x406bf364..394`；其状态并未在返回成功前再次强制检查。因此历史中“仅空 NCDT/NCVW 不足”仍成立，但不能进一步说“五个 payload 都必须非空才能通过这一外层函数”。

【反汇编证实】还识别可选 `NCM1`、`NCM2`，分别存 +0x38/+0x3c/+0x40、+0x48/+0x4c/+0x50。`0x406c0dd0` 的图像查询先拒绝 metadata 状态 2 或空解析结构指针；再依选择器取 NCTH/NCVW/NCM1/NCM2。NCVW 的一条分支接受 3840×2160、1920×1080、1280×720；另一缩略图分支接受 640×360，可能优先取 NCM1（长度上限 0x12800）；大缩略图分支优先 NCM2（上限 0xa5000），接受 1920×1080 或 1280×720。NCM1/2 不存在时可回退 NCVW。

**这些是 metadata 图像/缩略图接口的条件，不是 AVC SPS 的播放分辨率白名单。** 不能把 NCVW 要求解释为 Live 视频必须编码成 1080p。

【反汇编证实】`0x406bf84c`（内部函数起点）先调用图像查询，再要求所选 payload 非空且不超过输出容量，然后复制其字节。另有 NCDB 复制接口 `0x406c0c94..cb8` 检查非空和输出容量。尚未追完图像解码器、OP01/OP02 的所有消费者，不能指定 JPEG 压缩参数或声称 NCDB 空内容在所有路径都可用。

## NCTG 记录格式：已恢复部分

【反汇编证实】`0x406ce344` 转至 `0x406ce880`。该函数清零一个 0x1444 字节解析结构，再循环读 payload。每条先读四个大端 u16：tag 高半、tag 低半、type、count（合计 8 字节），后跟数据；按 type 查跳转表计算 count×1/2/4/8 的数据长度，检查不超过 payload。没有看到类似 TIFF IFD 的开头条目数或通用外部 value offset；这里是顺序记录流。循环进入要求剩余至少 9 字节。

【反汇编证实】tag 高/低半在一个 97 项、每项 0x40 字节的运行时表中查找，表基址 `0xa0297f658`。已知项还有 type/count 检查，部分 tag 允许可变 count，并通过回调解释数值。未知项依类型长度跳过；非法类型或越界退出记录循环。之后仍执行身份字符串比较并输出状态，因此“函数走到返回”不等于所有记录有效。

【反汇编证实】尾部比较解析结构中的厂商字符串与 `NIKON`，还将 +0x12、+0x22 处字符串与 MAIN 常量 `0x440c69fc`（文件字节证实为 `NIKON Z 8\0`）比较（相关代码 `0x406cead8..406cebc0`）。状态 0/1/2 和解析结构指针返回给外层。状态 2 在后续图像查询被拒绝。

【未恢复】97 项表的完整 tag→字段映射、全部类型回调、上述字符串的原始记录编码、NCTH/NCVW 有效图像码流、NCDB 的 OP 语义与 UI 对其失败的处理。不要用解析结构偏移 +0xc4 直接去改 NCTG 文件 payload；两者不是同一种布局。

## 最小块的明确边界

【推断，逐分支静态推演】以下 **66 字节**可满足已恢复的外层盒条件（包括 worker 的 udta 长度 >63），前提是低层 MOV parser 已成功、读取缓冲足够：

```text
udta size=66
  NCDT size=58
    NCHD size=18 payload=4e 69 6b 6f 6e 00 01 00 00 00
    NCTG size=8
    NCTH size=8
    NCVW size=8
    NCDB size=8
```

保存为 `tests/ncdt-structure-only.bin`。它只是**外层结构最小候选**，没有 ARM 仿真或实机验证。空 NCTG 跳过解析，初始状态 2/空指针保留；后续 `0x406c0dd0` 将拒绝，所以它**不是完整有效 metadata，更不是可播放方案**。没有把它注入测试 MOV，以免把已知不完整的块混入主要变量实验。完整有效最小块目前无法负责地合成。

## 需要怎样的原厂样本

当前文件夹的 MOV 只有给定 Live 样本，没有原厂 Z8 MOV。下一步需要用户另行提供：

1. **未经任何转封装、剪辑、导出或 metadata 清理的整份 Z8 原厂 MOV**，最好同一运行固件版本，H.264 8-bit SDR、1920×1080、29.97p 或 25p、带原厂音轨、横拍 3–5 秒；记录全部录制设置、文件名/DCF 目录、固件版本，并由用户确认原卡上可列出、显示缩略图、播放有声和正常返回。
2. 首先需要整份文件而非只截 NCDT：要比较 ftyp、udta/NCDT 所在位置、stsd、edit lists、sample tables、音频与未知盒。之后可以提取**完整 udta 原始字节**、各 NCDT 子盒哈希和边界，用作隔离实验模板。
3. 原厂竖拍及另一尺寸/帧率样本是后续差分所需，不是第一步的最低要求。若一个样本无法区分 NCTG 的视频尺寸、预览尺寸和身份字段，再增加第二份只改变一个设置的原厂录制。

【推断】原厂 NCTH/NCVW 图像和 NCTG/NCDB 是优先复用/差分对象，但“整段复制即可播放”尚未证实。直接复制可能显示错误缩略图、时长、方向和身份；先明确是否有内部引用、校验或视频相关字段，再做离线 donor 实验。原厂样本目前是得到可靠完整 metadata 和可播对照的必要证据输入；不声称物理上只能通过它解决。
