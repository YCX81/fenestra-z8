Nikon Z8 测试包 3g（Live v7：v6 + 写卡地址修正）
基础：测试包 3a（MAIN 919a6545）+ Live 修复 v1–v5 + 回放改动。版本标识 04.05.p0，以 SHA-256 辨认。

v6（e083c2d4）在你的相机上的结果
- 抓帧 2.2 ms、编码 7 ms，约 18 帧/秒，一段 90 帧；但每次写文件都在第一次读原 JPG 时报错 1：
  原厂读写文件接口不接受带缓存的别名地址（关掉 cached_work 后写文件就能进行，证实了这一点）。

v7 修正：调用原厂读写文件接口时传回同一物理内存的原地址；写前刷回缓存、读后作废缓存。
其余与 v6 完全相同，不需要再关 cached_work。

再往前（54cc3272）的结果
- DSC_9692 第一次完整写出 Live（JPG+MOV+LVP+MAN），机内回放能播放，RAW+JPEG 没问题。
- 但片段只有 7 帧（约 2 帧/秒）；机内回放画面横向变窄、很糊（预览只有 320×212）。

这一版改了什么
1. 提速（v5）：USB 实测取景缓冲、Wave5 缓冲、Live 自己的工作缓冲都映射成"不带缓存"（属性 0x44），
   同一块物理内存在地址 +0x400000000 处有"带缓存"的映射（属性 0xff）。现在：
   - 读取景画面：先逐页核对别名（同一物理地址、带缓存），作废缓存后从带缓存地址读；
   - Live 工作缓冲（画面、码流环、预览、MOV 组装区）改走带缓存地址，释放前刷回内存；
   - 写 Wave5 输入：写带缓存地址，交给硬件前刷回内存；读码流：先作废缓存再读；
   - 写卡前刷回源数据，读卡前后作废缓存。
   四处都可以用 USB 在线关掉（cached_lv / cached_work / cached_slot / cached_bs），不用刷机。
2. 机内回放预览改为 1024×682，与 Live 片段同尺寸、同比例（每张 LVP 约 47 MB，Live 内存约 64 MB；
   相机上实测内存池还能多给 64 MB，通用堆能同时给 1 MB + 3 MB）。旧的 320×212 预览（如 DSC_9692）仍能播放。
3. 回放画面铺满整张画布，比例与照片一致，不再横向变窄。

验证
- 电脑重放真机时序 5/5 通过；回放层：1024×682 帧转换、铺满画布、旧尺寸兼容、未知尺寸拒绝都在电脑上测过；LVP 文件头读写一致。
- QEMU（MAIN c9cd9160）：关闭 Live 单拍 2/2 正常；打开 Live 停在 Wave5（与 3a 相同）。
- 带缓存的走法只能在真机上验证（QEMU 没有抓到取景帧）。

注意：拍照时先不要插 USB。拍完等图标从 BUSY 变回 LIVE，再插 USB 读数据，读完拔掉。

测试
1. 刷机后打开 Live，等图标变绿，拍 1 张，等 5 秒再拍 1 张。
2. 回放全屏看这两张，按 REC：画面应清晰、不变形、比之前流畅。
3. 接 USB 让我读状态（帧率、各阶段耗时、带缓存走法是否生效）。若有异常，我可以在线关掉某一处带缓存走法。
