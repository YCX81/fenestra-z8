零（v48）、取景器
- 真机读到：眼睛贴近取景器时，Live 取的那路取景画面从 1024×682 变成 1280×852。
  以前 Live 会丢掉尺寸不对的帧：用取景器时 Live 完全不工作；拍照前后正好切换的那张会失败（变成普通照片）。
  而且“尺寸变了就重建”那段代码实际没有生效。
- v48：取景器的画面按比例缩到 1024×682 再编码，背屏/取景器来回切换不中断预录，Live 文件尺寸始终是 1024×682。
- 验证：主机测试（贴取景器 30/30 帧编码、切回背屏 30/30；缩放像素位置正确）；QEMU Live JPG+MOV（编码 920 帧）、REC 回放 45 帧通过。QEMU 没有取景器，取景器效果只能真机看。
- 为什么不按取景器的 1280×852 单独录：每次眼睛靠近/离开都要重建编码器、预录清零（又要等 1.5 秒），
  一张 Live 跨两种尺寸时没法拼；机内回放和以后的原厂播放器也要多支持一种尺寸。以后需要可以再做成选项。

零（v47）、修了什么
1. Live 图标：从回放、USB、菜单切回拍照后不出现，转屏时闪一下。
   - 真机读到：Live 已就绪、图标在刷新，但原厂把图标所在的图层关了；v44 加的“图层被关就重新打开”一次也没执行过。
   - 原因：v44 那段检查有个 C 运算符优先级错误（把“读出来的值 + 192”当成“地址 + 192”），条件永远不成立。v47 已改正，并核对了编译后的指令。
2. Live 写卡慢（真机日志：一张 Live 10.5～16.3 秒，其中机内预览的 45 张 JPEG 占 7.4 秒）。
   - 写卡时 Live 还在同一个 CPU 上继续采集/编码下一段预录，和写卡抢 CPU。v47 在写卡期间暂停预录编码（反正写完前不能拍下一张 Live），写完后预录重新开始（约 0.5 秒可拍短 Live、1.5 秒就绪）。
   - 生成预览 JPEG 时让出 CPU 的次数减到原来的 1/4。
   - 能快多少要看真机日志；彻底解决要等改用原厂播放器直接放 MOV（不再需要这 45 张预览图）。
3. 日志：v46 新加的两个事件编号和音频日志冲突，已改开（只影响诊断日志）。

仍未解决：快门声（需要对照实验，见下文第三节第 0 条）。

零（v46）、Live 就绪
- Live 打开后需要先攒 1.5 秒的预录画面才算“就绪”。v46 让你在屏幕上看得到这个过程：
  · 未就绪：Live 图标整体变灰（黑边不变），外圈 12 段虚线从 12 点方向顺时针随预录逐段变白；
  · 就绪：图标恢复全白（和以前一样）；
  · 保存中：和以前一样的扫光动画。
- 预录攒到 0.5 秒（外圈亮 4 段）以后按快门就会生成 Live，只是前段比 1.5 秒短；
  以前不到 1.5 秒按快门只会得到普通照片。Live 菜单的状态行此时显示 “Live Photo: Short clip”。
  已知限制：短 Live 的机内 REC 预览固定播 3 秒，片段不够时最后一帧会停留到 3 秒结束；MOV 本身长度正确。
- 从菜单、回放回来，或取景中断超过 1 秒：预录从头开始，不会再把进菜单之前的旧画面拼进 Live 视频。
  内存和编码器保留不释放，只是预录重新攒（约 0.5 秒可拍短 Live，1.5 秒完全就绪）。
- 切到录像档时 Live 仍会交还编码器和内存（录像要用），回到拍照档后重新申请，比从菜单回来多一点时间。

零（v45）、修复 Live 随机关闭
- 真机读到：开机时 Fenestra 还在决定用哪张卡，Live 在这段时间去读设置，读失败被当成“没有设置 = Live 关”；
  之后菜单里改任何一项（比如快门声）都会把这个“关”存成更新的一代设置。表现为开机或切菜单后没有 Live、照片只有一张。
- 修复：等选卡完成再读设置；读失败重试，不再当成“关”（30 秒仍读不到才用默认值）；设置读完之前的菜单操作先暂存。

零（v44）、修复从回放切回拍摄后 Live 图标消失
- 真机上读到：从回放切回拍摄画面时，原厂界面会把 Live 图标所在的图层关掉（图标对象还在、仍在“绘制”，但不上屏）。
  以前的检查只看是不是拍摄画面，没检查这个图层开关，所以图标一直不出现，直到重新开机。
- 修复：每次刷新图标时检查图层是否被关掉，关掉就重新挂接图标（挂接会重新打开图层）。
  在真机上手动重新打开图层后，原厂不会再反复关掉它，所以不会造成图标闪烁。

v43 的内容（保留）
v43 修了什么（v42 只插 SD 卡能激活，但拍下来只有照片，没有 Live）
- 真机上读 Live 的运行状态：Live 已开启，编码器一帧都没编出来，按快门因为没有视频片段而被忽略。
- 原因：从 v38 起 Live 改用 Wave5 的 H.265 编码。真机 Wave5 生成的 SPS 带有量化矩阵和 VUI，有 415 字节；
  Live 的参数集缓冲区只有 256 字节（QEMU 模型生成的 SPS 只有 40 字节，所以一直没暴露）。
  解析 SPS 失败 → 编码器启动失败 → 之后每一帧都重试失败。这和插哪张卡无关，v38～v42 在真机上 Live 都不会生成。
- 修复：SPS/PPS 缓冲区加到 1024 字节，VPS 256 字节；MOV 写入器同步加大。
- 用真机抓到的 VPS/SPS/PPS 在电脑上验证：解析、显示裁剪（688→682）和 MOV 的 hvcC 解析都正确。
- 保留 v42 的 SD 卡缓存修复（读写 SD 卡前后做 CPU 缓存维护，修复只插 SD 卡时插件 Panic 和写卡数据错误）。

一、FENESTRA 目录可以放在 SD 卡上
- 每次开机选一次 Fenestra 用哪张卡：
  · A 卡（CFexpress/XQD）上有 FENESTRA/ → 用 A，和以前完全一样。
  · A 卡上没有 FENESTRA/（或 A 槽没插卡），SD 卡上有 → 用 SD：插件、启动标记、Auto activate 设置、
    C64 的 SC*.REC 记录、Live 的设置文件都读写 SD 卡上的 FENESTRA/。
  · 两张卡都没有 → 按 A 处理，与以前相同。
- 两张卡都有 FENESTRA/ 时永远用 A。建议只在一张卡上放 FENESTRA/。
- 卡刚插入、还没挂载好时，Fenestra 会短暂显示 "Checking card"/"Card error"，挂载完成后自动重新检查，最长等 20 秒。
- 开机后才换卡：本次开机选定的卡不变，重启后重新选。
- 只插 SD 卡使用：把本包里的 FENESTRA/ 文件夹拷到 SD 卡根目录。

二、Live 双卡改动
- Live 的 MOV/JPG/MAN 写在“原厂照片 JPG 所在的那张卡”上：只插 A、只插 SD、主卡槽选 SD、溢出、RAW 主卡 + JPEG 副卡都按原厂照片走。
- 备份模式、JPEG+JPEG 模式：Live 先在第一张卡上生成，再把同一组 Live 文件补写到另一张卡（MOV 原样复制，配对 JPG 由那张卡自己的 JPG 生成）。
  两张卡文件夹编号不同或目标已有同名文件时不补写；补写失败会删掉半成品，第一张卡不受影响。
- 机内回放 REC 预览：改为按照片路径 + 文件大小找 Live 文件（以前按开机后卡挂载次数，两张卡同时插着时会找不到）。
- 回放里删除/保护照片时联动 Live 文件：A、SD 两张卡都生效；插拔卡后自动重新开始。
- Live 诊断日志（LIVEDATA/LIVELOG.BIN）写在 Fenestra 所在的卡上。
