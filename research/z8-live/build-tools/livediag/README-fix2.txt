Nikon Z8 测试包 3c（Live 修复 v2，带诊断计数）
基础：测试包 3a（MAIN 919a6545）+ Live 修复 v1 + v2。版本标识 04.05.p0，相机里显示的版本号不变，以 SHA-256 辨认。

v1 在你的相机上的结果（USB 实测）
- 抓帧修好：复制一帧从 417 ms 降到 27 ms，201 帧成功 198 帧，图标能变绿。
- 但编码一帧要 435 ms（每秒只有 1.8 帧）；拍照时取景尺寸会变，原代码因此清空缓冲、重新申请内存，
  而拍照处理中内存池被锁，申请失败后 Live 永久停在失败状态；按快门时缓冲里没有 1.5 秒前的关键帧，快门被忽略。

v2 修了什么（只改 Live）
1. 编码输入/输出改为整块读写：输入帧 Y 整块写入 Wave5 缓冲，色度在缓存里交错好一行再整块写；码流整块读入缓存再解析。
2. 取景尺寸变化时只跳过这些帧，不清空缓冲；没在录片段且尺寸持续变化超过 3 秒时才按原来的方式重置。
3. 申请内存失败时继续等待，下一帧再试，不再永久失败。
4. 找不到快门前 1.5 秒的关键帧时，用快门前最早的关键帧开头（片段变短，但不丢）。
预期：拍完不再长时间橙色；片段能写出（帧率取决于真机编码速度，待测）。

验证
- 抓帧转换函数与编码整块复制函数：在 Unicorn 里用编出的机器码测试，结果与参考逐字节一致（3 + 6 种情况）。
- QEMU（MAIN d33c2238）：关闭 Live 单拍 2/2 正常；打开 Live 连拍停在 QEMU 没有模型的 Wave5 寄存器写入处，与 3a 原版相同。
- 与 3a 相比只有 Live 代码区和其原有的 15 个挂钩点不同。

测试
1. 刷机后打开 Live，停在取景等图标变绿，拍 1 张，等 5 秒，再拍 1 张。
2. 回放全屏看照片左上角是否有 LIVE，按 REC 能否播放；卡上 LIVE\100NCZ_8 是否有同名 JPG+MOV。
3. 接 USB 让我读诊断数据（必要时手动打开 USB Debug），读完拔线。
