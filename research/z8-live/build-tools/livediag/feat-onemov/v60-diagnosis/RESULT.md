# V60 新拍 Live 无标志、播放无响应：并行诊断

2026-11-15。用户实机反馈：V60 拍摄 Live 后回到回放，没有 Live 标志，按播放键没有反应。后续确认：9085–9090 均无标志，重启不恢复，旧 Live 仍有标志。已只读检查挂载的 SD 卡并在 `card-20261115/` 保全相关配对记录、MOV、日志和文件清单。

**新卡证据将问题分成两部分：9086–9088 未生成 Live；9085、9089、9090 已有完整 Live 文件，但用户回放仍未识别。** 后三张的真实 MAN、原图大小及 MOV 结构均通过离线识别检查。当前尚未测得相机回放实际使用的卡槽、照片路径和文件 I/O 返回值，因此未确认后三张无标志的根因。

之前复现的失败缓存不重查是真实的旧缺陷，但不能单独解释“文件已保存、重启后仍无标志”。应与本次尚未解决的识别问题分开。V60 回放 worker 首次读取 `.MAN` 配对记录失败后，只在当前照片 ID 改变或离开回放后才重新查找；同一张照片的记录即使稍后写完，也不会自动恢复识别。

本次完成了三个并行分支：回放入口、拍摄冻结与写入、构建及既有 QEMU 证据核对。新增内容限于此诊断目录；未改生产补丁、交付包或相机，未连接相机 USB 或刷机，原卡仅只读检查。

9085 保存约 6.309 秒，完成后约 1.903 秒恢复 READY；因此现有单片段流程不能为保存期间的每张连拍都生成 Live。日志与五张原厂 JPG 的文件时间按同一开机偏移对齐，最大残差 7.1 ms，但日志没有直接记录照片编号。详见 [日志分析](capture-log-analysis.md)。

卡上的固件文件 SHA256 也精确匹配 V60。9085/9089/9090 的 MAN 都记录 `B:\DCIM\108NCZ_8\DSC_xxxx.JPG`，记录的大小与原图一致；generation 分别为 3/3/2。将真实 MAN 和原图大小送入原样 V60 lookup + sync.c，正确 B/JPG 输入全部通过，media_epoch 为 1 或 3 都通过；generation 本身不是拒绝原因。见 [实际 MAN 识别测试](cache-repro/card-lookup-results.json)。

9084 对照与三张新片均为 1024×682 HEVC、30000/1001 CFR，NCDT/NCTG、样本表和媒体范围正确；四片都通过 ffprobe 和 ffmpeg 音视频全片解码。按 V60 `mov_size()` 的原子遍历逻辑均接受。9085/9090 的音轨全零，9089 有非零音频；这是额外的录音现象，不能解释徽标缺失。见 [MOV 结构验证](card-20261115/mov-structure.json) 及同目录的 `DSC_*-decode.json`。这些离线结果不证明真机播放稳定性。

旧 9084 在 SD 上同时有 JPG/NEF，新六张仅有 JPG。代码确认 Live 只跟随 JPG，双卡补写只针对另卡同名 JPG；不会在仅有 NEF 的主卡建立 Live 配对，回放 lookup 也不跨卡找 JPG。**“RAW 主卡 + JPEG 副卡，而回放选中主卡 NEF”是符合现象的候选，用户尚未确认此设置，不能当成结论。**

回放缺陷的实际控制流证据见 [生成的 V60 runtime.c](cache-repro/generated/pb-fix37/runtime.c)：`lookup()` 第 285 行开始先清 `cache_valid`；MAN 读取、解析、原图路径或大小核对失败时返回。worker 第 341 行只有 `id != lastid` 时调用 lookup。徽标和 REC 入口共同依赖 `cache_valid`。

[离线复现结果](cache-repro/results.json) 中，首次 MAN 缺失，随后令文件可读，保持同一张照片运行 4 秒，仍只有一次读取、`lookup_error=2`、`cache_valid=0`、没有徽标请求、REC 不接管。切到其他照片再切回，或离开回放后重新进入，都会再次读取并恢复。媒体事件也会清除缓存，但同 ID 没有自动重查。相反，仅 `ui_leaving=1` 会阻止徽标，却不会单独阻止 REC 接管；700 ms 按键抑制和 stage 3 的 2.5 s 延后清理在用例中均会恢复。

另一个已排除的单独解释：MOV 宽高解析失败只让 `nb_w=0`，会阻止播放启动，但此时 MAN 验证已令 `cache_valid=1`，因此不能独自解释两个现象同时出现。

拍摄侧仍有不同的可能性：writer 只有在 MOV 成功关闭后才写 MAN；事务失败会清理本次拥有的 LIVE JPG、MOV、MAN。若新拍文件根本没有保存，修复回放重试并不能恢复不存在的短片。V60 剪帧位置没有新增失败跳转，现有边界测试也未发现其破坏配对或写入参数，但不据此排除硬件运行中的其他失败。详见 [冻结测试说明](freeze/README.md) 和 [结果](freeze/results.json)。

已有播放测试 `pom8f/pom8n` 使用正式 V60 MAIN，但把先前生成的文件放在预置卡上、重新启动 QEMU 后播放；所以这些测试也没有覆盖 MAN 尚未提交时第一次进入回放的时序。

下一步先确认拍摄的双卡设置和回放当前卡槽。选择 SD 卡上的 9085/9089/9090，或在关机状态下只保留这张 SD 卡后检查其标志，可区分跨卡/NEF 候选。若明确选择 SD/JPG 仍无标志，则需要运行时诊断：current_id、407b95e4 返回路径、lookup_error、各 open/seek/read/close 状态及原图实读大小。现有 LIVELOG 不包含这些 PB 识别字段，不能仅凭目前文件确认是哪一项在机内失败。

旧的缓存问题可另行通过 worker 限频重试无效缓存修复，保留 MAN 与原图身份校验、媒体切换处理及原厂播放桥接期间的门控，并补同次开机的拍摄到回放回归。它不应冒充本次“重启仍无标志”的已确认修复。当前未发布新的修复固件。
