# 真实 v52 G 录音检查（只读副本）

输入是 root 从 SD 只读复制到 `feat-v53/card-v52` 的 DSC_9060～9063，均用 inventory SHA 验证。未改卡、未接相机。四条都有 48 kHz 双声道 LPCM 24-bit 音轨；实际有效位为 16-bit，低 8 bit 全零。MOV soun 和 LVJB 指向同一 PCM 数据。独立 ffmpeg 完整解出的 s16 PCM SHA 与本地逐块提取四条全部一致。

|9061|3.269938 s|0.057417 s|1.735066 s|-23.16|0|

|9063|3.169833 s|0|1.634967 s|-21.12|10 / 304304|

9060、9062 的零样本分别延续到拍照 marker 之后约 1.0913、0.8273 s，所以不能仅解释成少了一段拍前缓存。音频 edit list 只有 14/6/1/5 微秒的起点对齐，不是长静音原因。9061 的 1.70231～1.85238 s、9063 的 1.59825～1.74829 s 是约 150 ms 的零段，与当前曝光 duck 的 50 ms before +100 ms after 一致，单独列出，不混作启动缺陷。

三个开头有静音的样本，首个非零 frame 都是 L 先非零、R 为零，下一 frame 双声道非零，随后立即有正常幅度。这与 ADC/codec 起声相符，但单靠文件不能判定是 codec 何时解除静音、回调延迟，还是哪一段核心缓存被补零。不能把此推断写成唯一真机根因。

当前增益是 `runtime.c:live_audio_ticket_get` 的 **软件乘 4 并饱和截断**，不是 ADC 提高 12 dB；后端仍默认 `LAZ8_ADC_0DB=0x1c0`。四条所有非零 s16 样本都是 4 的倍数，未见旧版只放大半个 interleaved block 的 4×/1×签名。9063 有 10 个 -32768、12 个接近满刻度样本；4×可能造成少量削波，不能宣称绝对响度/音质已经理想，也没有依据盲目统一降增益。录音场景不相同，跨片 RMS 不是受控的增益对照。

当前复制的 LIVELOG/LIVEPREV 是后续启动会话：head 3/4，仅 EV25/23，未包含拍照或音频时间线。没有记录不能推导拍照代码未执行；它们不足以区分这两条长静音的硬件起因。照片 EXIF 在现阶段不会给出 codec unmute/历史首帧时间，未额外读取相机或物理卡。

证据：`analysis.json`、`ffprobe.json`、`timing-tracks.json`、每条 `*-10ms.csv` 与 `.s16le`，以及输入 `card-v52/inventory.json`。录音文件质量与 REC 扬声器输出是两条不同验收项；这些非零 PCM 不证明相机 REC 已可听。
