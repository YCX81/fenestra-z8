# v53 竖屏状态布局：最终严格增量

候选 MAIN SHA-256 `4d96fdd4fcca46c343e70691af6858675708b5c36812240d8791bbf9ca7db188`，基于交付的 v52 G。修改 77 条完整 68-byte 记录中的竖屏矩形，实际变化 284 bytes。横屏、PNG、字体、样式、原厂照片记录及其他固件代码保持原样。未重算 build ID / bootguard，此步骤由 root 集成工具负责。

## 这次证实的错误

v52 的几何测试只证明原厂能取到作者给定的矩形，不能证明示意图中的控件名称正确。此前 `Format` / `FPS` 的标签确有误认：group54/56 是外部输出 REC/STBY，group75 是同步状态，group68 是 ASSIST。不能继续把它们当作用户所说的三个标签。

本次沿真实更新函数执行到绘制辅助函数，再从原厂 PNG 表读资产，身份如下：

| 真实控件 | 组 | 原厂更新函数 | 本例实际资源 |
| --- | --- | --- | --- |
| 2160/30p 复合图标 | 34 | `4041a0ac` | 前景 `768` 64×32；背景 `769` 68×36 |
| FX 画幅 | 37 | `4041a9ac` | 前景 `84d` 36×32；背景 `9a7` 40×36 |
| H.265 10-bit | 73 | `4041e140` | 前景 `a04` 82×32；背景 `a62` 86×36 |

实际 ARM 查询找到 codec enum 2/3、format key 45 的 2160/30p 配对，未通过替换资源 ID 伪造结果。`4041ecb4 → 40414018` 使用前景/背景行：LCD 两行都有对象；EVF 对应背景 ID 为 0，只有前景。`4032b1c0..4032b208` 的原厂居中计算为 `(框尺寸-资产尺寸)/2`。三组 EVF 前景各有 2px 留白，LCD 背景填满各自的框。

## 最小修正

三个标签统一按“分辨率／帧率、画幅、编码格式”的顺序排在右侧第 2、3、4 状态行。保留图标原尺寸和原厂字形居中；H.265 的文字本身比标签板窄，不把文字改成右对齐。

| 模式 | 三个框的右界 | 实际标签板右界 | 分辨率／FX／codec 的行顶 |
| --- | --- | --- | --- |
| LCD 两表 | 476 | 476（双层背景） | 50 / 94 / 138 |
| EVF normal | 894 | 892（前景） | 60 / 112 / 164 |
| EVF small | 828 | 826（前景） | 134 / 186 / 238 |

LCD 只需把分辨率框从右界 440 移到 476。EVF 原分辨率右界 470/536（normal/small）确实位于中央，FX 原来在第一行，codec 边距也不一致；此次三者进入同一右侧列。

EVF 的 REC 与普通已录时长移到第 2 行中央，保留 8px 间隔。长时间码保持单独第 5 行，与 LCD 的语义一致；时间码和普通时长是替代状态，不同时绘制。原厂真实计时更新的 16 组测试证明开启 TC 时优先更新 TC，否则更新 elapsed。

为给右侧分辨率让出位置，EVF 原在顶右的“剩余录像时长＋卡标”移到底部状态区。small 模式音量/麦克风条只左移 12px，避免卡标覆盖；按全部复合控件边界计算，audio→card→remaining→原厂计数之间的空隙为 6 / 4 / 5px。normal 对应空隙为 110 / 4 / 30px。未假设旁边未识别的控件必然隐藏。

`layout-review.png` 是使用实际原厂 PNG 的代码绘制示意，**不是相机截图**；计时文字为说明性占位字体。对照覆盖 LCD、正常 EVF、小画面 EVF。左右竖向都由原厂 policy 选择相同的 P 矩形，实际方向旋转仍由原厂输出层负责，不为第二个方向另造镜像坐标。

## 验证与边界

- `layout-machine.json`：最终候选 308 次原厂 ARM 查表/复制（修改前后×横/竖），另 16 个 gate / auto-rotate / pose 组合，均通过。
- `resources-arm.json`：7 次真实资源 updater 身份、2 个真实分辨率 enum、18 次原厂居中运算；三种显示模式的实际标签板右边界一致。
- `timer-machine.json`：最终表的 16 次原厂 timer 更新和 LCD/EVF cache 选择通过，包含 normal/small 和 TC/elapsed 优先级。
- `integrity.json`：全部表的横屏/样式/资源未变；照片映射完整记录未变；77 个错误原记录反例都拒绝；独立代码修改可保留；保守包围盒无新增目标控件重叠。

这些证据覆盖真实 ARM 的资源选择、矩形选择、计时分支和居中算法；字体渲染、对象分配、显示后端为明确的测试边界。没有宣称整机竖屏取景画面或真机目视验证通过。没有 USB、相机、物理卡操作，也未更改 QEMU 模型。

## 集成契约

依赖仅 `portrait53.py` 和同目录 `layout_data.py`：

```text
python3 portrait53.py INPUT OUTPUT --reference V52_G_MAIN
```

`reference` 必须整镜像 SHA 为 `ed1e8496fccde443412e527a252de5029a55c749053b9b046da42bfc454aa613`。`INPUT` 可包含独立 v53 代码更新，不要求整镜像 G SHA，但所有 77 条受影响完整记录必须与 G 一致，任何差异立即拒绝。不能在已应用本补丁的镜像上重复运行。可直接调用 `apply(image, reference)` 取得 `(new_image, edits)` 加入 root 的 aggregate manifest。
